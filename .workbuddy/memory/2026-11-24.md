### ⚠️ 重要环境坑（下次别再踩）
- **本环境 `next dev` 的 HMR WebSocket 连接失败**（`net::ERR_INVALID_HTTP_RESPONSE`），
  导致页面**不 hydrate**：DOM 节点上无 React fiber（`Object.keys(el)` 为空），
  所有 useState/useEffect 都不生效——表现为滚动交互"没反应"，其实是 dev 坏了，
  不是代码问题。**验证交互功能一律用 `next build` + `next start`**，
  生产环境 DOM 有 fiber、交互正常。
- 用 `rm -rf .next` 清缓存会被安全策略拦截（文件数 >1000），别再试。
- 判断 hydration 是否成功：`Object.keys(document.querySelector('header')).length`，
  生产为 2、坏掉的 dev 为 0。
- 预览地址：用户要实时看 UI，用 dev 服务器 `http://127.0.0.1:3000`。
- **dev 不 hydrate 的真正根因（已解决）**：Next.js 16 默认拦截来自 `127.0.0.1` 的
  `/_next/webpack-hmr` 跨域请求，报错 "Blocked cross-origin request to Next.js dev
  resource"，导致 JS/HMR 加载失败、React 不 hydrate（DOM 无 fiber、交互全失效）。
  解决：`next.config.ts` 加 `allowedDevOrigins: ['127.0.0.1']` 并重启 dev。
  之前误判为代理问题（HTTP_PROXY）——其实清空代理没用，是这个跨域白名单。
  验证 hydration：`Object.keys(document.querySelector('header')).length`，hydrate 后为 2。
  无头浏览器测 dev 时加 `--no-proxy-server` 启动参数，避免 WS 被本地代理拦截。
